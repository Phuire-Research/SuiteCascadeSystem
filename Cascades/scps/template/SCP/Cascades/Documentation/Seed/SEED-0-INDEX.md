# THE METHOD SEED v1

The Seed is the acquired case law of the Suite Cascade System, shipped beside the constitution. The constitution (the project's CLAUDE.md manifold) defines the method's structure — Suites, Gates, Crystralines, the Ego-Lambda Pair. The Seed carries what the method LEARNED while operating: seventy-two laws distilled from the full operational record, each one paid for in the field, generalized so no originating project can be reconstructed. The constitution says what the method is; the Seed says what the method knows.

Every law keeps one shape: **The Law** (bolded, one sentence) · **The Failure Mode** (what it cures) · **How to Apply** (the operational cure). The register is doctrine for agents to absorb and apply — not narrative, not history.

## THE INDUCTION CONTRACT

The Seed is read by the Induction Agent of a fresh install and converted into project memory. The contract:

1. **One memory file per law (or per tightly-bound law cluster).** Each file carries frontmatter:
   - `name:` the law's title as a kebab-case slug (e.g. `probe-before-salvo`)
   - `description:` the law's one-line essence
   - `type: feedback`
   and a body holding the law's full three-part shape (The Law · The Failure Mode · How to Apply).
2. **One index line per file** appended to the project's MEMORY.md: `[Law Title](filename.md) — the one-line essence.` The index line stays under ~200 characters; the detail lives in the topic file.
3. **Read-back verification per write.** Every memory file written is read back before the next is written; the induction ends with a count Concluder (files written vs laws inducted) — the induction obeys the very Lambda discipline it is seeding.
4. **The agent inducts method it can APPLY, not prose it can quote.** Each memory entry must be operable as a decision rule at the moment its trigger appears (a dispatch, a Write, a sleep, a guard, a menu). If a law cannot be phrased as something the agent will DO differently, the induction of that law is not complete.
5. **Selective depth is legitimate.** A fresh install may induct the six theme docs as six cluster files first (name, description, and the doc's checklist as the body) and split individual laws out as they start firing. The checklists at the foot of each doc are the compressed operational form.

## The Versioning Law

**The Seed rides the SCP update circuit.** It ships inside the template's Documentation, so every install carries the Seed version current at install time, and every template update carries the Seed forward. Re-induction refreshes: when an updated Seed arrives, the Induction Agent re-runs the contract — new laws induct as new files, changed laws overwrite their file (Read-back verified), and the MEMORY.md index reconciles. Project-local memory minted by the project's own cycles is never overwritten by re-induction — the Seed seeds; the project's own record grows beside it.
