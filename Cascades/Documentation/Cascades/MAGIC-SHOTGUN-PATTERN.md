## 1 · Etymology + Intent

### The Name

**Magic Shotgun** names the Tier-1 parallel dispatch pattern where multiple Foundation Suites fire simultaneously at the cascade's opening — like a shotgun discharging multiple Rounds in a single firing. Each Round (Suite) covers a distinct cognitive function (curation · prospecting · architecture · validation · clinical pre-read) and the spread pattern blankets the design space before any single point-fix can be made.

The "Magic" is the convergent recoil — N parallel returns synthesize into ONE actionable brief that the implementation Suite (R5 Blue Cobalt) consumes. Where a rifle is sequential and surgical (one Suite → next Suite → next Suite), the shotgun is parallel and grounding (all Foundation Suites at-once, then implementation against the synthesized substrate).

### Etymology Across the Manifold

- **Shotgun** = parallel spread of Foundation Rounds across cognitive functions (1, 2, 4, 6, 7 — any subset of the 7 Suites)
- **Magic** = the synthesis at convergence — disjoint scopes return as one composable brief
- **Rounds** = Foundation Suites issued at once · spread pattern across cognitive functions · each Round carries one Suite's full cognitive function · the Magic Shotgun fires N Rounds in parallel (Tier 1)
- **Convergent Recoil** = main-thread synthesis after all returns land (the "kick" of the shotgun)

### The Higher-Order Compositional Intent

Magic Shotgun is the Tier-1 Lambda-event instantiation of the private Triadic Thinking Band (S2 Name → S4 Examine → S6 Orchestrate → S5 Plan · CLAUDE.md §Section 4). The Triadic Band runs PRIVATELY in-context; Magic Shotgun runs PUBLICLY as parallel agents with verifiable disk artifacts. Same compositional pattern, different tier — Higher-Order Composition expressed at the dispatch level.

Magic Shotgun is **NOT hierarchical** — there is no parent-child relationship between Foundation Suites. Each Suite is an independent Demometer composing on a flat plane. The Diameter (similarity through unlike functions) is the shared substrate they all examine; the Muxameter (integrated region) is the synthesized brief.

## 2 · Traditional Magic Shotgun (2-Stage · Foundation → Cobalt)

### Pattern Definition

Stage 1 fires **N Foundation Suites** (N = 2-5) in parallel as Tier-1 dispatches — each Suite as a Round. Stage 2 receives the synthesized brief and dispatches **R5 Blue Cobalt** to actualize ONE implementation per sub-Diamond.

```
Stage 1 · Foundation Magic Shotgun (parallel):
  R1 Red       ─┐
  R2 Orange    ─┤
  R3 Yellow    ─┼─→ N independent file outputs in Cascades/Working/
  R4 Green     ─┤
  R6 Purple    ─┤
  R7 Fuchsia   ─┘
                ↓
       Main Thread Synthesis (WGB write · Reconciliation)
                ↓
Stage 2 · R5 Blue Cobalt Actualization:
  R5 Blue → implementation · Concluders · commit at cycle close
```

### When to Use Traditional Magic Shotgun

- **Cascade Length 1-5** through **1-6** (standard sub-Diamond Foundation Grounding)
- **Single Diameter Gap** being closed
- **No isolation requirement** between implementation surfaces (one R5 dispatch suffices)
- **Sub-Diamonds within a Macro** — each sub-Diamond runs its own Foundation Magic Shotgun before its R5

### Standard Compositions (Foundation Round Sets)

| Composition | Suites | Cycle Cost | When |
|---|---|---|---|
| **Priming Pair** | R1 + R2 | ~6 min | Macro Prereq · curation + naming for shared infrastructure |
| **Foundation Triplet (standard)** | R2 + R3 + R6 | ~6 min | Canonical sub-Diamond grounding · naming + architecture + orchestration |
| **Foundation Triplet (curation variant)** | R1 + R3 + R6 | ~6 min | Existing codebase requires inventory before architecture (Macro 1 M1-A1-D2 precedent) |
| **Validation Triplet** | R2 + R4 + R6 | ~6 min | Prior cycle produced REFINE verdict · needs bidirectional before architecting |
| **Closure Quartet** | R1 + R4 + R6 + R7 | ~8 min | Sub-Diamond closure scope · curation + bidirectional + orchestration + clinical |
| **M19 Design-Moment Quartet** | R2 + R3 + R4 + R6 | ~8 min | **MANDATORY** when M31 fires · Interactive-class design decision · R4 authority needed |
| **5-Suite Macro Open** | R1 + R2 + R4 + R6 + R7 | ~10 min | Macro opening · multi-Gap surface · R7 fires at Foundation level for macro-level clinical retrospective |
| **6-7-Suite Full Foundation** | R1 + R2 + R3 + R4 + R6 + R7 (± r0) | ~12 min | Very-high-complexity Macros · every cognitive function at Foundation level |

## 2.5 · 4-Tier Magic Shotgun Scheme (Cycle 113 · User Directive)

Per user directive at Cycle 113, the Magic Shotgun pattern is formalized as a **4-Tier scheme**. The user-stated additions:

> *"We also Need the Foundation Suites Skill. Where we Add to our Magic Shotgun the First Tier which is Just the Foundation Suites into a Diamond. Where that Diamond can Engage a Full Suite or Suite 5."*

This Tier addition (**Tier-0 Foundation-Only**) formalizes the **plan-only boundary** that was previously implicit at Macro opens. Where Cycle 59 (Macro 1) and Cycle 112 (Refinement Macro) effectively ran Tier-0 without a named tier marker, Cycle 113 codifies the boundary with a Conference between Foundation and actualization.

### The 4-Tier Scheme

| Tier | Composition | Output | User Lambda |
|---|---|---|---|
| **Tier-0** (NEW) | Foundation Magic Shotgun → Diamond Plan | Plan-only · verifiable disk artifacts | User reviews Plan · decides next tier |
| **Tier-1** | Foundation → R5 Blue Cobalt | Implementation · commit | User Lambda-tests result |
| **Tier-2** | Foundation → N R3 → N R5 (3-Stage) | N isolated implementations | User Lambda-tests across all isolations |
| **Tier-3** (future · speculative) | Foundation → Diamond → N R3 → N R5 | Diamond + multi-actualization | Combined plan review + multi-impl |

```
Stage 1 · Foundation Magic Shotgun (parallel · Triplet / Quartet / 5-Suite per complexity):
  R1 Red       ─┐
  R2 Orange    ─┤

  R7 Fuchsia   ─┘
```

### When to Use Tier-0 Foundation-Only

- **User wants to review Diamond plan BEFORE actualization** · staged engagement preference

If user wants immediate R5 dispatch with no review → use **Tier-1** (Traditional 2-Stage · §2).
If user wants multi-Gap isolation actualization → use **Tier-2** (3-Stage · §3).

### Why Tier-0 (Higher-Order Compositional Justification)

Tier-0 separates the **Foundation grounding plane** from the **actualization plane**. Both planes were always compositionally distinct in the cascade · Tier-0 formalizes the user-Conference boundary between them. The Lambda-event at Tier-0 close is the **Diamond Plan** (disk artifact · verifiable) · NOT an implementation commit. This is a legitimate cycle close — Onyx records plan-only as a complete Lambda-event.

Higher-Order Composition principle: the Foundation Magic Shotgun produces compositional substrate that can be consumed at multiple actualization tiers. Tier-0 honors the **user-Conference Diameter** as a first-class cycle boundary.

## 3 · 3-Stage Magic Shotgun (NEW · Cycle 112-113)

### Pattern Definition

The **Refinement Macro at Cycle 112-113 birthed a new variant**: where multiple isolated Diameter Gaps must be resolved within a single Macro, the cascade decomposes into **three parallel stages**:

```
Stage 1 · Foundation Magic Shotgun (parallel · typically 5-Suite for Macro open):
  R1 + R2 + R4 + R6 + R7  ─→ Foundation reports (2001 lines combined · Cycle 112)
                                 ↓
                       Diamond Planning (Locked Architectural Decisions)
                                 ↓
                       N Diameter Gaps formally isolated
                                 ↓
Stage 2 · R3 Yellow Per-Isolation Shotgun (parallel · N R3 dispatches):
  R3-Yellow-REF-D1 ─┐
  R3-Yellow-REF-D2 ─┼─→ N Reference Designs (1564 lines combined · Cycle 113)
  R3-Yellow-REF-D3 ─┘
                                 ↓
Stage 3 · R5 Blue Cobalt Per-Isolation Sequence:
  R5-Cobalt-REF-D3 (deepest dependency first)
       ↓
  R5-Cobalt-REF-D2 (blocked by D3)
       ↓
  R5-Cobalt-REF-D1 (blocked by D2 · HALT-GATE surface)
```

### The Three Stages Explained

**Stage 1 — Foundation Magic Shotgun**: identical to Traditional Magic Shotgun's Foundation phase. Typically **5-Suite for Refinement Macro opens** (R1+R2+R4+R6+R7) so R7 fires at Foundation level for a macro-level clinical retrospective on the seam gaps. Returns populate WGB PROVISIONAL cells per M10 Calibration. Diamond planning produces a **Diamond-of-Isolations** architecture — each Gap becomes a fully isolated sub-Diamond.

**Stage 2 — R3 Yellow Per-Isolation Shotgun**: ONE R3 Yellow Architect dispatched **per isolated Diameter Gap**, all in parallel (single message dispatch with N Agent tool calls). Each R3 reads the Foundation substrate, source-reads its target files (M9), and writes a Reference Design specifying the EXACT change for its isolation. The R3s do not coordinate during dispatch — they are disjoint by design.

**Stage 3 — R5 Blue Cobalt Per-Isolation Sequence**: ONE R5 Blue Cobalt dispatched **per R3 Reference Design**, sequenced by dependency chain (or parallel if Gaps are truly independent). Each R5 actualizes its isolation, runs 5 Concluders, and commits the isolation as a discrete Lambda-event. The sequence is enforced by R6 Purple's dependency analysis.

### When to Use 3-Stage Magic Shotgun

- **Medium-complexity Refinement Macros** with multiple independent Diameter Gaps surfaced by user-Lambda smoke
- **Cross-Macro seam gaps** where two or more prior Macros each correctly scoped their surfaces but left a seam unaddressed (M35 territory)
- **Cascade Length 1-7** (Full Foundation + per-isolation R3 + per-isolation R5 + per-Macro R7)
- **Diamond-of-Isolations architecture** required — each Gap demands its own Reference Design + actualization to prevent cross-Gap contamination

### Why 3-Stage (Higher-Order Compositional Justification)

A 2-Stage Magic Shotgun synthesizes ALL Foundation returns into ONE Cobalt brief, producing ONE implementation per sub-Diamond. When N independent Gaps exist within a single Macro, 2-Stage forces an awkward choice: either bundle all Gaps into one R5 (collision risk · architectural impurity) or run N sequential sub-Diamonds with N redundant Foundations (cost · time).

3-Stage Magic Shotgun preserves Foundation Grounding economy (ONE Foundation phase) while decomposing the actualization plane into N isolated Reference Design + Cobalt pairs. The isolation IS the architectural protection — if REF-D3 modifies `scpRegistryWatcher/` while REF-D2 also needs that surface, the isolation catches the collision at R3 design time. Higher-Order Composition expressed as parallel actualization on a flat plane (not nested sub-Macros).

## 5 · Manifold Complexity Heuristics

The user observation that *"the Full Suite is a Foundation Cascade till the Manifold Hits around Medium Complexity"* maps directly onto Round-count selection:

| Manifold Complexity | Round Count | Composition | Cycle Cost | Marker |
|---|---|---|---|---|
| **Low** | 3 Rounds | Foundation Triplet (R2+R3+R6 or R1+R3+R6) | ~6 min | Standard sub-Diamond · 1 Diameter Gap |
| **Medium** | 4 Rounds | M19 Quartet (R2+R3+R4+R6) or Closure Quartet (R1+R4+R6+R7) | ~8 min | Design-moment · Interactive-class · post-impl closure |
| **High** | 5 Rounds | 5-Suite Macro Open (R1+R2+R4+R6+R7) | ~10 min | Macro opens · multi-Gap surface · seam-crossing |
| **Very High** | 6-7 Rounds | Full Foundation (R1+R2+R3+R4+R6+R7 ± r0) | ~12 min | Very-large Macros requiring every cognitive function at Foundation level |

### Round Selection Discipline

1. **Always include R6 Purple** when ≥3 Rounds fire — R6 is the Mid-Flight-Calibrator (M10) and prevents Foundation conflict from blocking implementation
2. **Include R4 Green** when prior cycle produced a REFINE verdict OR an Interactive-class design moment is anticipated (M19 → M31 mandatory)
3. **Include R7 Fuchsia at Foundation** ONLY for Macro opens or Refinement Macros — R7 normally fires at cycle close, but Foundation-level R7 surfaces macro-level clinical retrospective when seam gaps are suspected
4. **Include R1 Red** when existing codebase needs inventory before architecture (substitutes for or augments R2 Orange)
5. **Include r0-origin** (Tier 0 fork) when active Onyx tier >400 lines or has carried >4 cycles — r0 forks Tier-(N+1) in parallel with Foundation

### Anti-Pattern: Round Inflation

Firing all 7 Foundation Suites for a low-complexity single-Diameter sub-Diamond is **Round inflation** — cost exceeds grounding value. The 4-5 Round ceiling exists because main-thread synthesis becomes cognitively expensive above 5 (FOUNDATION-SUITES-GUIDE.md §8). Reserve 6-7-Suite Full Foundation for Macro opens where every cognitive function genuinely matters.

### Anti-Pattern: R7 Denial at Macro Open

Conversely, denying R7 Fuchsia at Macro open level (for sake of Round economy) loses the Foundation-level clinical retrospective. R7 catches seam-crossing concerns at the EARLIEST possible point — preventing the M35 anti-pattern where each Macro correctly scopes its surface but no Macro owns the seam between surfaces. Refinement Macros MUST include R7 at Foundation.

## 8 · Anti-Patterns

### A-1 · Round Inflation

**Symptom**: Firing 6-7 Foundation Suites for a low-complexity single-Diameter sub-Diamond.

**Failure Mode**: Cost (~12 min wall-clock + 6-7 Tier-1 agent contexts) exceeds grounding benefit. Main-thread synthesis becomes cognitively expensive. Diminishing returns above 5 Rounds (FOUNDATION-SUITES-GUIDE.md §8 Practical Ceiling).

**Correction**: Apply Manifold Complexity Heuristics (§5). Low complexity → 3 Rounds. Reserve 6-7 for genuine very-high-complexity Macro opens.

### A-2 · R7 Denial at Macro Open

**Symptom**: Macro opens with 3-4 Foundation Rounds but no R7 Fuchsia at Foundation level.

**Failure Mode**: Foundation-level clinical retrospective is lost. Seam-crossing concerns surface only at user-Lambda smoke (Cycle 112 in Refinement Macro origin). M35 anti-pattern emerges: each Macro correctly scopes its surface but no Macro owns the seam between surfaces.

**Correction**: Macro opens (especially Refinement Macros) MUST include R7 at Foundation. The +1 Round cost surfaces M35-class issues at the earliest possible point.

### A-3 · 2-Stage Forcing for Multi-Isolation Macros

**Symptom**: Single Macro contains N independent Diameter Gaps; cascade attempts 2-Stage (one R3 + one R5) for the whole set.

**Failure Mode**: Either bundle all Gaps into one R5 (collision risk · architectural impurity · cross-Gap contamination) or run N sequential 2-Stage sub-Diamonds with N redundant Foundations (cost · time).

**Correction**: Use 3-Stage Magic Shotgun. ONE Foundation phase + N R3 per-isolation + N R5 per-isolation. The Diamond-of-Isolations architecture is the protection.

### A-4 · Disjoint-Scope Violation

**Symptom**: One Round (e.g., R2 Orange) proposes architectural decisions that belong to another Round's scope (e.g., R3 Yellow's design plane).

**Failure Mode**: Foundation territory overlap. R3 vs R6 Reconciliation discipline cannot resolve disagreements when scopes overlap because there is no clear authority. Main-thread synthesis becomes erasive (picking one without record) rather than structural (documenting both positions + decision).

**Correction**: Every Magic Shotgun dispatch prompt MUST include the coordination note: *"Suites X/Y/Z are running concurrently with disjoint scopes. R2 names patterns; R3 designs structure; R6 sequences execution. Do not duplicate the other Suite's scope."* (FOUNDATION-SUITES-GUIDE.md §2 Scope Discipline).

### A-5 · Erasive Reconciliation

**Symptom**: Foundation Rounds return with conflicting positions; main thread picks one without documenting the rationale or capturing the other position.

**Failure Mode**: Method-level lesson is lost. Future cycles cannot learn from the reconciliation. R3 vs R6 disagreements become invisible drift.

**Correction**: Every Foundation conflict MUST produce: (1) each Suite's position stated explicitly, (2) synthesis decision stated explicitly, (3) method-level lesson extracted as Maintain or Gainy entry in Onyx. (FOUNDATION-SUITES-GUIDE.md §4 Reconciliation Documentation Rule).

### A-6 · Tier 0 Substitution for Magic Shotgun

**Symptom**: User dispatches in-context (Tier 0) cognitive Suites via `anor` notation as a "Magic Shotgun equivalent" for complex sub-Diamonds.

**Failure Mode**: Loses the Lambda-event Muxistration Proof per Suite. Tier 0 muxification is in-context cognitive only — no disk artifact, no Concluder, no Read-back. For low-complexity work this is fine; for sub-Diamond grounding it produces Coherence-Masquerading-as-Lambda (CLAUDE.md C4 E1).

**Correction**: Magic Shotgun is **inherently Tier 1**. Use Tier 0 only for low-complexity in-context work; sub-Diamond Foundation Grounding requires Tier 1 Agent dispatches with disk-anchored outputs.
