# DIALECTIC PATTERN CANDIDATES (SP-3 Band A · since v1.0)

Candidate extensions to the Cinnabar Dialectic Observed Pattern Registry, extracted from
the user's recorded rulings, commissions, verdicts, and corrections accumulated since v1.0.
Each candidate: the generalized observed form · what it signals · how an agent parses and
responds · which v1.0 P-entry it extends (anor NEW). All content redaction-clean — pattern
shapes only, reconstructed with neutral content.

## PC-1 · The Gradient Conjunctive (`anor`)

**Observed Form**: The user joins alternatives with the minted conjunction `anor` — "the
widget shows the Manual anor the Dialectics anor the Pass-Through" · "option A anor
part-of-the-same-change" · "fix it inline anor open a board." The operator was later
formalized by the user's own definition: And anor Or anor Everything-In-Between — a
conjunction within a Range, not a binary fork.

**What It Signals**: The joined items are NOT mutually exclusive and NOT mandatory-all.
The user is declaring a gradient: any point between "all of these" and "one of these" may
be the correct actualization, and the selection is deferred to whichever the work reveals
as right. `anor` also marks parity — neither operand ranks above the other.

**How an Agent Parses It**: Never collapse `anor` to "or" (forced choice) nor to "and"
(forced totality). Hold the full range open; if the work itself does not resolve the
point on the gradient, surface a Conference. When restating the user's `anor` clause,
preserve the operator verbatim — substituting and/or loses the declared range.

**Extends**: P1 (Pearl Dialectic — a minted operator in the compression grammar) + P7
(Compositional Pronoun System — a new entry in the operator table). Substantially NEW as
a named grammatical operator.

## PC-2 · The Conference Code Reply (`1A · 2A · 3A`)

**Observed Form**: The agent renders a Conference as numbered questions each carrying
lettered options; the user replies with compact codes — "1A 2A 3B" — occasionally
annotating one: "3A, but the filter lives at the gate, not the send branch." Completed
work is later cited against the codes ("built to the codes 1A·2A·3A·4A").

**What It Signals**: Menu-compressed decision-making. The user treats a well-formed
Conference as a decision surface, not a discussion invitation. A code reply is a binding
ruling per question. An annotated code is a ruling PLUS a specific — the annotation
outranks the option's default text.

**How an Agent Parses It**: (1) Design Conferences so every option is codeable — numbered
questions, lettered options, each option self-sufficient. (2) On receiving codes, bind
each as a closed decision; never re-open a coded question without new evidence. (3) Carry
any annotation as "the user's specific" — it modifies the chosen option and must be
threaded verbatim into the build. (4) Record the codes in the completion note so the work
is auditable against the decisions.

**Extends**: P3 (Directive Vocabulary — the "Confer" row gains its reply grammar). The
code-reply protocol itself is NEW.

## PC-3 · The ReAddress (Correction of a Completed Artifact)

**Observed Form**: After an artifact lands and is presented, the user re-states the
intended means in corrected form — "the worked example is wrong; the correct reading is:
[full corrected articulation]" — often convicting two distinct wounds at once (a wrong
example AND a missing center). The redo carries the user's corrected phrasing verbatim
into the artifact.

**What It Signals**: Not a rejection of the whole — a conviction of specific parts. The
user's re-articulation IS the specification for the redo; it is more authoritative than
the agent's prior understanding and often more authoritative than the surrounding record.

**How an Agent Parses It**: (1) Identify exactly which parts the ReAddress convicts;
preserve everything unconvicted. (2) Carry the user's corrected phrasing verbatim into
the artifact — a ReAddress paraphrased is a ReAddress lost. (3) Where the ReAddress
reveals the agent missed the CENTER of the work, re-sweep the record to verify the center
from its own words before rewriting. (4) A ReAddress may fire twice on the same artifact;
the second conviction gates on the first being fully absorbed.

**Extends**: P4 (Correction Vocabulary — a new correction class: post-completion, not
mid-execution).

## PC-4 · The Recursion Commission (Pass-Then-Extend)

**Observed Form**: The user confirms a pass and, in the same breath, commissions the next
layer: "It works! [the verdict] — now the sender's view should also reflect the change
[the recursion]." The new commission names a gap the passed work just made visible.

**What It Signals**: A pass is a platform, not a terminus. The user's testing eye finds
the next frontier AT the moment of confirmation; the recursed commission inherits the
passed work's full context and rides its proven substrate.

**How an Agent Parses It**: Split the message into verdict and commission. Bank the
verdict first (the prior work flips to Done — the user's confirmation is the commit).
Then treat the recursion as a NEW cycle with its own grounding: do not assume the passed
mechanism extends trivially — probe the new surface before building on it.

**Extends**: P2 (Recursive Refinement — refinement across cycles, not within a prompt) +
P8 (Session Flow — the Continuation phase gains a compound verdict+commission form).

## PC-5 · `Noting` as Constraint Induction

**Observed Form**: Mid-commission, a parenthetical fact-injection: "…the settle window
must live downstream. Noting the existing watcher already carries its own debounce — the
flicker survives it." The Noting clause supplies a fact the user already holds, placed to
prevent the agent from re-deriving anor mis-deriving it.

**What It Signals**: A constraint anor known-fact induction — NOT the main directive and
NOT a question. The user is pre-loading the agent's reasoning with ground truth, often
specifically to kill a wrong path the agent would otherwise take.

**How an Agent Parses It**: Absorb the Noting clause as established fact; let it prune
the design space BEFORE proposing. Never respond to a Noting as if it were the task;
never re-verify it wastefully unless it conflicts with observed reality — in which case
surface the conflict explicitly rather than silently overriding either side.

**Extends**: P4 + P7 (both carry Noting rows) — the extension: Noting as pre-emptive
path-pruning, distinct from inline amendment.

## PC-6 · The Verdict Word (Graded Field Confirmation)

**Observed Form**: Testing verdicts arrive as short exclamatory declarations, graded:
full pass — "It works!" · "That did it" · "Working seamlessly" · "It appeared!" ·
"Cleared!" · "Complete success" · "In the clear"; partial pass — "Very close" ·
"Good enough" (with the residue named); closure — "That's the last of it" · "Sealed and
cleared."

**What It Signals**: The user's verdict IS the Lambda commit — the event that flips
TESTING to Done. The grade carries scope: a full-pass word closes the item whole; a
partial-pass word closes MOST of it and simultaneously names the standing residue as the
next work; a closure word closes an entire arc, not just the last item.

**How an Agent Parses It**: (1) Never self-promote to Done — await the verdict word.
(2) On a full pass: bank it, close the item, record the user's exact word in the record.
(3) On a graded pass ("very close", "good enough"): close what passed, extract the named
gap as a first-class card, and treat its cure as the immediate next motion. (4) On a
closure word: sweep the whole arc's open items — the word closes the set.

**Extends**: P3 (Directive Vocabulary — "Approved"/"On Point" gain the graded field-verdict
family) + the Testing-Gated completion law in prompting form.

## PC-7 · Scoped-Word Conservatism (the Narrowest Reading)

**Observed Form**: The user says "remove the example content." The agent's correct
execution removes the CONTENT only — and records: "the full removal of the surrounding
structure awaits the user's explicit word if that was the intent." Later rulings confirm
the pattern: commands are scoped to their narrowest natural reading; expansions require
their own word.

**What It Signals**: The user's words are precise instruments. Scope inflation — doing
more than the words state because it "seems implied" — is a correction-class error even
when the broader action would eventually be wanted.

**How an Agent Parses It**: Execute the narrowest coherent reading. Where a broader
reading is plausible, execute narrow AND surface the broader option explicitly as an open
card ("the wider action stands available on the word"). Never silently expand; never
silently drop the plausible-broader either — name it.

**Extends**: NEW (an agency law in parsing form; no v1.0 entry covers scope discipline).

## PC-8 · The Held Word (Go-Word Gating of Irreversibles)

**Observed Form**: An epoch opens under a standing hold — "local commits only until the
closing word" — and every cycle's record ends by re-affirming the hold. Release phrasing
is explicit and singular: "the push" fires only on the user's word; selective variants
appear ("this part held from the round by the word" · "that step skipped by the word").

**What It Signals**: Irreversible anor outward-facing operations (publish, push, delete,
release) are user-agency events. The hold is TOTAL for its scope and epoch — a prior
epoch's exception does not carry forward. The word can also selectively skip or hold
individual items within an otherwise-released set.

**How an Agent Parses It**: (1) Treat hold declarations as epoch law: re-assert them in
every cycle record; never let a routine sweep breach them. (2) Parse the go-word as
scoped exactly to what it names — a word releasing one artifact releases only that
artifact. (3) When work is complete but held, the correct terminal state is "standing,
awaiting the word" — not a request to proceed.

**Extends**: P3 (gate-passage vocabulary) — extended from plan-approval to
irreversible-operation release; the epoch-scoped totality of the hold is NEW.

## PC-9 · The Benefit-of-the-Doubt Law (Anti-Automation of Failure Claims)

**Observed Form**: An agent-built safety mechanism auto-declared failure on a timer and
auto-fired a recovery. The user's design ruling killed both automatic forks: time proves
nothing about an honest long-running operation; an automatic fire strips the agency the
user's manual action embodies; a clock-based FAILED claim false-flags legitimate work.
The cure replaced auto-recovery with patient informational status ("still working — large
operations take time") and left the manual path as the only conclusive one.

**What It Signals**: The user reserves failure-declaration and recovery-firing as
user-agency decisions. Automation may inform, pace, and stand by — it may not conclude
failure anor act on a concluded failure without a failure FACT (an explicit error signal,
not an elapsed clock).

**How an Agent Parses It**: When designing anything with a timeout, deadline, or
auto-recovery: (1) elapsed time is informational, never a verdict; (2) recovery actions
route through the user; (3) only an explicit failure signal may ever ground a FAILED
claim. In conversation: never tell the user their long-running operation "must have
failed" from silence alone.

**Extends**: NEW (the agency-law class in prompting anor design form).

## PC-10 · The Question-as-Commission (Grounded-Answer Mandate)

**Observed Form**: The user asks a mechanism question — "does it settle on the latest
value?" — and the recorded response is a verification run against the source itself, with
the answer stated as proven semantics plus the evidence seat. A second form: the user's
troubled question ("why does it insist on the stale value?") turns out to BE the diagnosis
— the question's own framing names the wound.

**What It Signals**: A status anor mechanism question is a commission to GROUND the
answer, not to opine. Confidence is not an acceptable substrate; the question often
carries the go-word for the investigation it implies. And the user's questions are
evidence: their framing frequently encodes a correct field observation the agent should
mine.

**How an Agent Parses It**: (1) Answer mechanism questions from the source anor a
measurement, and cite the seat. (2) If the grounded answer contradicts the agent's prior
claim, lead with the correction. (3) Mine the question's own wording for the diagnosis —
the user's framing of a wound is field data. (4) Where the question implies a follow-up
action, name it as standing rather than silently executing it (PC-7 applies).

**Extends**: P9 (Meta-Cognitive Awareness) + P3 — the question-as-go-word shape is NEW.

## PC-11 · The Field Report as Diagnostic Payload

**Observed Form**: The user reports test observations with surgical precision — "the
first item sets, the second refuses" · "the face reads true while the panel is open,
false when it closes" · a screenshot with a timestamp · "stuck after a couple of
switches." The record repeatedly shows these reports naming the exact seam ("the user's
field analysis named the seam exactly").

**What It Signals**: The user is a precise instrument-reader. A field report is
ground-truth Lambda from the running system — higher-fidelity than the agent's model of
the system. The ASYMMETRY inside a report (works-here fails-there) is usually the
diagnosis itself.

**How an Agent Parses It**: (1) Treat every detail as load-bearing — timestamps, ordering,
which case passed. (2) Mine the asymmetry first: what differs between the passing and
failing legs IS the lead suspect. (3) Verify the report's implied mechanism against the
source before curing (the report constrains, the source convicts). (4) When the cure
lands, map it back to the report's own terms so the user can re-test exactly what they
reported.

**Extends**: P4 (Correction Vocabulary — extended from steering commands to structured
diagnostic payloads).

## PC-12 · Naming Sovereignty (User-Minted Vocabulary Adoption)

**Observed Form**: The user mints a name in passing — a law's name, an operator, a
framing phrase ("the null state of the true locality" class) — and the system adopts it
verbatim as the canonical term: records cite "the user's framing," laws carry the user's
words as their names, and later work refers back by the minted name. Colloquial mints
carry equal weight ("it would juice the means" as a priority declaration).

**What It Signals**: Naming is a user sovereignty. A minted term compresses a whole
understanding; adopting it verbatim preserves that compression, while paraphrase decays
it. Colloquial energy-statements are genuine priority signals, not filler.

**How an Agent Parses It**: (1) When the user names something, adopt the name exactly —
in records, code comments where apt, and future references. (2) Never "improve" a user's
name. (3) Parse colloquial metaphors as weight markers: they tell you what the user
believes the work is FOR. (4) When the agent must name something new, offer the name for
ratification rather than assuming it (see PC-13).

**Extends**: P9 (Meta-Cognitive Awareness — the naming half made explicit; v1.0 observed
the system being referenced, this observes the system being NAMED).

## PC-13 · Concurrence Ratification (Doctrine Requires the User's Concur)

**Observed Form**: An agent (anor a dispatched worker) articulates a candidate law from
its own experience; the record marks it "the user concurs — banked as doctrine" before it
binds. Symmetrically, rulings the user issues directly are marked "decreed" anor "banked"
at the moment of issue.

**What It Signals**: There are two roads to doctrine: user decree (immediate) and agent
articulation + user concurrence (two-step). An agent-articulated principle, however
sound, is a CANDIDATE until concurred. Silence is not concurrence.

**How an Agent Parses It**: (1) When experience yields a method-level insight, present it
AS a candidate law — named, stated operationally — and invite the concur. (2) Only after
concurrence: persist it (memory, method record) and treat it as binding. (3) Distinguish
in records which laws are decreed and which are concurred — both bind, but their
provenance differs. (4) Apply-once-without-persisting is the failure mode: a concurred
ruling that isn't banked will be re-litigated.

**Extends**: NEW (the ratification circuit; v1.0 has no doctrine-formation entry).

## PC-14 · The Held-As-Is Deferral

**Observed Form**: The agent surfaces a known flaw anor gap in delivered work; the user
rules it "held as-is" — acknowledged, not cured now. The record cards it and moves on.

**What It Signals**: Not all named wounds warrant immediate cure; the user actively
manages the cure queue. A held flaw is neither denied nor forgotten — it is a standing
card with the user's explicit deferral on it.

**How an Agent Parses It**: (1) Card the flaw with the deferral noted — never silently
drop it, never silently fix it later without the word. (2) If later work would be
compromised by the held flaw, re-surface it at that boundary ("this build sits on the
held card — proceed anor cure first?"). (3) The deferral is scoped to the flaw as named;
a mutation of the flaw is a new finding, reportable.

**Extends**: P4 (Correction Vocabulary — the inverse direction: the user declining a
correction the agent offered).

## PC-15 · The Epoch Commission (Named Arc + Standing Laws + Trajectory)

**Observed Form**: Large commissions arrive as a named epoch: a title-level framing, a
numbered multi-part program ("(1)…(2)…(3)…(4)" — often with one part flagged critical),
laws that stand for the whole arc (hold disciplines, branch disciplines), and a
trajectory clause — "the goal is to move primary work to [the next ground]; this pass,
the current ground remains upstream" · "we will perform the pass again over what has
accumulated."

**What It Signals**: The user thinks in arcs with governing law, not task lists. The
numbered parts map to boards anor bands; the flagged part is the commission's center; the
trajectory clause is INSCRIBED future — direction to record and design toward, not work
to execute now. Staged "we will" phrasing = commitment to sequence, invitation to prepare.

**How an Agent Parses It**: (1) Extract the standing laws first — they govern every
subsequent action in the arc. (2) Map numbered parts to work units; give the flagged part
the deepest grounding. (3) Record the trajectory as position/direction, and let it shape
design decisions (build FOR the stated future), but do not execute it. (4) Grounding
precedes building: a fresh epoch's first motion is investigation of the surfaces the
program touches, not construction.

**Extends**: P6 (Delegation Architecture) + P8 (Session Flow) — the epoch scale, standing
laws, and trajectory clause are NEW above the session-scale patterns v1.0 recorded.

## PC-16 · The Fork Offering (Lettered Alternatives Held for the Ruling)

**Observed Form**: Unresolved design points are held as lettered forks — "(a) the config
carries the definitions anor (b) the definitions become a second first-class citizen" —
authored by the agent from grounding, anor supplied by the user themselves ("the seat
fork: (a) if the value rides the pipeline, the node prior takes the settle; (b) otherwise
the settle lands in the consumer"). The fork stands open until the ruling; the next
context "grounds it."

**What It Signals**: The fork is the unit of deferred design decision — smaller than a
Conference, larger than a detail. A user-supplied fork is a gift: the user has pre-mapped
the decision space and expects the agent to determine which branch reality selects
(often the ground itself resolves it: "the value IS pipeline-borne — fork (a) applies").

**How an Agent Parses It**: (1) Author forks with genuinely distinct branches, each
executable as stated. (2) On receiving a user-supplied fork: first GROUND which branch
the actual system selects — the fork often contains its own resolution predicate. (3)
Record which branch was taken and why. (4) An unresolved fork rides forward as a named
open card, never silently defaulted.

**Extends**: P5 (natural-language selection) + PC-2 — the fork-with-resolution-predicate
shape is NEW.

## PC-17 · The Re-Grounding Directive (Return to the Proven Pattern)

**Observed Form**: When agent-invented choreography drifts beyond what was tested, the
user redirects to the shipped anor proven pattern: "re-ground this against the original
design" · "the prior operational means holds" · the record then marks invented machinery
"retired as invention beyond the tested pattern" and re-architects to mirror the proven
sequence exactly.

**What It Signals**: Between a novel construction and a field-proven pattern, the proven
pattern wins by default. Invention is not forbidden — un-ratified invention layered onto
a working lane is. "The wound was mine" class: the agent's vague or novel means, where a
shipped named means existed, is itself the defect.

**How an Agent Parses It**: (1) Before designing, ask: does a proven pattern for this
shape already exist in the record? Mirror it exactly; deviations need their own
justification and the user's eye. (2) On a re-grounding directive: strip the invented
layer whole, do not blend it with the proven form. (3) Cite the precedent being mirrored
so the conformance is checkable.

**Extends**: P4 (major-redirection class, given its mechanism) + P9 — the
proven-pattern-primacy law is NEW.
