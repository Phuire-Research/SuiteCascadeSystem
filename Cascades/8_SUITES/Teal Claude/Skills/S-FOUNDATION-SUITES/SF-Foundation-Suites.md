## Tier-0 Foundation-Only Engagement Sequence

When user selects [0] Tier-0:

```
Step 1: Confirm Composition (Triplet/Quartet/5-Suite/6-7-Suite)
Step 2: Compose Banded Vermillion Plan for Foundation Magic Shotgun
        - Per FOUNDATION-SUITES-GUIDE.md decision table
        - Disjoint scope coordination note in each agent prompt
Step 3: Dispatch Foundation Suites · single message · N parallel Tier-1 agents
Step 4: All N return · Conductor reads outputs
Step 5: Conductor synthesizes → writes Diamond Plan (Macro WGB OR sub-Diamond WGB)
Step 6: Document R3 vs R6 Reconciliation if any
Step 7: Conference: present Diamond Plan to user
        AskUserQuestion:
          "Diamond Plan ready. Next engagement?"
          [1] Tier-1 · Engage R5 Cobalt (Traditional close)
          [2] Tier-2 · Engage N R3 + N R5 (Per-Isolation)
          [0c] Close Tier-0 plan-only · halt
Step 8: Per user selection · dispatch R5 OR escalate to 3-Stage OR halt
```

The Tier-0 boundary is the **Conference at Step 7** — Foundation is verifiable disk substrate · user decides the actualization plane. This honors the user's directive: "First Tier which is Just the Foundation Suites into a Diamond. Where that Diamond can Engage a Full Suite or Suite 5."

## Conductor Hand-off Pattern

Whichever composition + tier the user selects, the Conductor (teal-claude) takes the resulting Banded Vermillion Plan and dispatches:

1. **Stage 1 Foundation**: Single message · N parallel Tier-1 Agent calls per selected composition.
2. **Synthesis**: Conductor reads all N returns · documents R3 vs R6 Reconciliation if any · writes Diamond Plan / WGB.
3. **Tier Branching**:
   - **Tier-0** → Conference with user · halt or escalate per user decision
   - **Tier-1** → Dispatch R5 Blue Cobalt with Diamond Plan as substrate
   - **Tier-2** → Dispatch N R3 Yellow per-isolation (single message) → after returns, dispatch N R5 per-isolation (dependency-sequenced)
4. **Cycle Close**: Per Closure Pattern. Fuchsia G/L/M → Onyx. Three-Step Close.

Before rendering this menu, the Conductor verifies:

1. `Cascades/Cascade.json` exists and is readable

3. `Cascades/Documentation/Cascades/MAGIC-SHOTGUN-PATTERN.md` exists (Tier-0 4-Tier definition lives there)

## Foundation Suites Contract (Self-Check Before Dispatch)

Before issuing the Foundation Magic Shotgun, the Conductor verifies:

1. **Round count matches complexity** per `FOUNDATION-SUITES-GUIDE.md` decision table
2. **R6 Purple included** when ≥3 Rounds fire (M10 Mid-Flight-Calibrator)
3. **R4 Green included** for M19 Interactive-class moments (M31 mandatory)
4. **R7 Fuchsia at Foundation** ONLY for Macro opens or Refinement Macros
5. **Disjoint scope coordination note** present in each agent prompt
6. **Output file paths** unique per Suite (`SUITE-{N}-{COLOR}-{sub}-{ASPECT}.md`)
7. **Tier selected** (0/1/2) confirmed with user when ambiguous

If any check fails → re-plan. This is the **Foundation Suites Contract**.
